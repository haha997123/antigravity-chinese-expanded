# 新版适配与边缘界面检查

## 项目文件

- `patch.js`：同版本原版备份、ASAR 校验、主进程与本地页面注入、动态句式和边界控制。
- `dictionary.json`：固定界面与说明词典。条目数不代表所有未来服务端文案均已覆盖。
- `features/chinese-title-*.js`：可选新会话中文标题服务。
- `tests/*.cjs`：翻译边界、通知、时间、标题、项目删除及归档安全检查。
- `docs/KNOWN-ISSUES.md`：跨版本问题和验证边界，修改后同步维护。

## 更新前核对

读取实际 `resources/app.asar` 中的 package.json、当前补丁标记、官方备份版本及哈希。不得把旧版 `.bak` 用于新版。保留本次原版、测试报告和回滚途径，但不将原版程序上传仓库。

需要同时检查 Electron 的 `dist` 模块和 `resources/bin/language_server.exe` 中嵌入的前端；只查 ASAR 会漏掉模型页、自定义配置和会话界面。只读提取资源供本地分析，汉化仍通过补丁进行，不修改原生可执行文件。

2026-11-18 的实际比较：2.32.1 与 2.32.2 的 ASAR 差异只有 package.json，嵌入前端 main.js 相同，但语言服务原生文件哈希不同。这个结论只适用于当次样本，不能推断后续版本也相同。官方自动更新覆盖补丁曾导致本机恢复英文。

## 必查入口

| 入口 | 容易遗漏的分支 |
| --- | --- |
| 首次启动、空项目、新会话 | 加载中、空列表、报错、欢迎语、无权限、首次消息及后续消息的时间 |
| 模型选择与使用情况 | Starter、Plus、Pro、Ultra、不可用、Notice、感叹号浮层、AI 积分不足、额度耗尽、每周及数值小时限额 |
| 模型公告 | 标题、正文、忽略按钮、模型名称及日期变化、付费方案差异、未开通订阅时的隐藏提示 |
| 自定义配置 | 已安装与市场、更多插件、展开详情、示例请求、技能介绍、账号、MCP 参数缺失、认证、启动失败 |
| 自动化 | 空列表、计划说明、凭据即将到期、已过期、暂停、失败及状态浮层 |
| 项目和会话管理 | 排序、分组、搜索无结果、分享失败、重命名、删除确认、进行中和已归档数量、Swarm 组合说明 |
| 会话执行 | 任务状态、工具卡、文件变更数量、权限确认、固定产品问卷、代码块工具栏；不要翻正文和原始工具输出 |
| 设置及反馈 | 高级设置、键盘快捷键说明、通知偏好、浏览器服务、隐私说明、表单校验与提交失败 |
| 右键与原生弹出菜单 | 会话、项目、分组、消息、链接、媒体、文件查看器、侧边标签页、输入框、内置浏览器与快捷键胶囊的右键菜单及递归子菜单（`Copy`、`Fork`、`Split`、`Move to Group`、`Sort By`）；需同时核对 `dist/preload.js`、`dist/main.js`（`Menu.buildFromTemplate`）与 DOM `context-menu-popup`，保留 `Move to Group` 用户自定义分组名与 WSL 发行版名，处理 `message-timestamp` 相对时间与浏览器 `Forward` → `前进` |
| 操作系统界面 | 托盘、系统完成/提问/授权通知、窗口标题、更新器和启动错误；页面 DOM 翻译覆盖不到这些 |
| 可访问性 | aria-label、title、placeholder 与可见文字不一定相同；输入框的 value 不属于翻译目标 |

不能触发的订阅或错误分支应从当前资源定位原文，并通过隔离测试验证；记录“源码及模拟验证”，不要写成已在真实订阅账号逐页验证。

## 实现和验证步骤

1. 记录英文原文、版本、进入步骤及源码位置，排除名称、模型正文、代码、日志和接口字段。
2. 对固定文案增加词条，对数量、日期、模型和时长使用完整句式。组合节点使用已确认的结构，不拆词后做全局替换。
3. 确认初始翻译、延迟挂载、字符变化、属性变化和重新渲染都能命中；同一中文结果重复观察不得写回造成循环。
4. 增加有实际意义的回归：当前问题、变化的数值/名称、相同文本出现在消息/代码/输入值时不变。
5. `npm ci --ignore-scripts` 后运行 `npm test`。真实 ASAR 隔离验证需确认全部修改模块语法可解析、unpacked 清单和哈希不变、还原精确等于原版，并保留报告。合成夹具通过不能替代真实包验证。使用 `@electron/asar` 在同进程中覆写或重构同名 ASAR 后再次读取时，必须先调用 `asar.uncache(archive)` 避免读取到旧头偏移缓存。
6. 保存工作，检查任务状态再重新应用。在 Antigravity 内工作时不可强杀宿主进程（`language_server.exe` 属于 `Antigravity.exe` 进程树，且运行中 `app.asar` 在 Windows 上被锁定），应完成隔离包验证后提示用户退出客户端，再从桌面「Antigravity 中文」启动以应用。启动后核对菜单、目标入口和通知。旧通知中心条目不会因为安装补丁自动改写，需要区分新通知。
7. 更新问题台账和版本适配范围。未测的版本不要加入支持列表；内部接口变化时停止相应功能，保持客户端可用。

## 本机启动器

桌面「Antigravity 中文」快捷方式调用 `launch-local.cmd`。词典和补丁保存在 Antigravity 安装目录以外的 `%LOCALAPPDATA%\AntigravityChinesePatch`。官方更新清空安装资源时，从已验证的同版本原版重新生成补丁，保留之前补过的词条。

启动器按客户端实际版本选择汉化。已逐版核对的原版 ASAR 使用完整补丁。后续 2.x 稳定版会核对程序及 ASAR 版本、归档结构、已验证的预加载和窗口模块指纹。匹配时仅追加已有的界面翻译，保留原生菜单、通知、更新器和标题服务。检查失败时打开原版并在启动器中提示。全新原文需要补词条。

启动器在客户端正常退出后应用，通过原版备份支持还原，重复启动时校验已安装的补丁并跳过重建。恢复英文时先正常退出，在补丁目录运行 `node patch.js --revert --no-kill`。使用 `node tests/ui-compat.cjs` 可从已验证的 2.34.0 原版 ASAR 构造未来版本样本，核对兼容、拒绝和还原分支。

Google 更新器、开始菜单、任务栏和其他入口可直接打开官方客户端。若更新器重启后先显示英文，正常退出客户端，再通过桌面「Antigravity 中文」打开。启动器没有常驻进程。

## 在线词典

稳定 Release 附件使用 `antigravity-chinese-dictionary.json`，包含 `schemaVersion`、`version`、`dictionary` 和可选的 `uiProfiles`。附件版本与 Release 标签一致。更新器读取 GitHub 公共 API 记录的 SHA-256，校验后写入独立缓存。定期检查失败时沿用最近验证过的缓存。口径不变的译文用字典追加，兼容记录需以经过实际验证的 preload 与窗口模块哈希成对录入。

完整包与词典附件中的字典应来自同一个 Git 标签。测试验证网络失败、散列不匹配、版本不回退和已验证兼容记录的行为。个人 `local-dictionary.json` 独立保存，优先应用。

## 发布

发布标题写明主要适配的 Antigravity 版本；正文写兼容验证、改动和限制。ZIP 采用明确文件清单，排除客户端文件、临时文件、用户数据及依赖目录。发布后独立下载 ZIP 和校验文件，核对标签、主分支提交、文件数和 SHA-256，再确认其他客户端版本的最终包仍公开可下载。

当前保留映射为 2.32.1 → v1.0.6、2.32.2 → v1.0.8、2.33.0 → v1.0.9。未来同客户端版本的新修订替换该组的保留目标，不跨组清空。
