# 新版适配与边缘界面检查

## 项目文件

- `patch.js`：同版本原版备份、ASAR 校验、主进程与本地页面注入、动态句式和边界控制。
- `dictionary.json`：固定界面与说明词典。条目数不代表所有未来服务端文案均已覆盖。
- `features/chinese-title-*.js`：可选新会话中文标题服务。
- `tests/*.cjs`：翻译边界、通知、时间、标题、项目删除及归档安全检查。
- `docs/KNOWN-ISSUES.md`：跨版本问题和验证边界，修改后同步维护。

## 新窗口接续

从 `D:\反重力汉化` 开新窗口时，先读该目录的 `AGENTS.md`，再进入 `%LOCALAPPDATA%\AntigravityChinesePatch` 维护源码。开始前查看 `git status --short`，保留本机待发布或只在本机使用的修改。应用前重新核对已安装版本和原版备份。

固定模型提示写入 `dictionary.json`。含 `Leaving on ...` 的提示复用 `patch.js` 中针对已收录说明的下线日期翻译。核对不同日期、模型名、未收录说明及正文保护，并在 `docs/KNOWN-ISSUES.md` 记录当前漏译和验证结果。

## 更新前核对

读取实际 `resources/app.asar` 中的 package.json、当前补丁标记、官方备份版本及哈希。不得把旧版 `.bak` 用于新版。保留本次原版、测试报告和回滚途径，但不将原版程序上传仓库。

需要同时检查 Electron 的 `dist` 模块和 `resources/bin/language_server.exe` 中嵌入的前端；只查 ASAR 会漏掉模型页、自定义配置和会话界面。只读提取资源供本地分析，汉化仍通过补丁进行，不修改原生可执行文件。

2026-11-18 的实际比较：2.32.1 与 2.32.2 的 ASAR 差异只有 package.json，嵌入前端 main.js 相同，但语言服务原生文件哈希不同。这个结论只适用于当次样本，不能推断后续版本也相同。官方自动更新覆盖补丁曾导致本机恢复英文。

## 实现和验证步骤

1. 记录英文原文、版本、进入步骤及源码位置，排除名称、模型正文、代码、日志和接口字段。
2. 对固定文案增加词条，对数量、日期、模型和时长使用完整句式。组合节点使用已确认的结构，不拆词后做全局替换。
3. 确认初始翻译、延迟挂载、字符变化、属性变化和重新渲染都能命中；同一中文结果重复观察不得写回造成循环。
4. 增加有实际意义的回归：当前问题、变化的数值/名称、相同文本出现在消息/代码/输入值时不变。
5. `npm ci --ignore-scripts` 后运行 `npm test`。真实 ASAR 隔离验证需确认全部修改模块语法可解析、unpacked 清单和哈希不变、还原精确等于原版，并保留报告。合成夹具通过不能替代真实包验证。使用 `@electron/asar` 在同进程中覆写或重构同名 ASAR 后再次读取时，必须先调用 `asar.uncache(archive)` 避免读取到旧头偏移缓存。
6. 保存工作，检查任务状态再重新应用。在 Antigravity 内工作时不可强杀宿主进程（`language_server.exe` 属于 `Antigravity.exe` 进程树，且运行中 `app.asar` 在 Windows 上被锁定），应完成隔离包验证后提示用户退出客户端，再运行对应安装包中的 `install.cmd`。启动后核对菜单、目标入口和通知。旧通知中心条目不会因为安装补丁自动改写，需要区分新通知。
7. 更新问题台账和版本适配范围。未测的版本不要加入支持列表；内部接口变化时停止相应功能，保持客户端可用。

## 手动应用和还原

选用与本机 Windows Antigravity 版本匹配的安装包。v1.2.4 起，ZIP 包含汉化脚本、词典、安装和还原入口、Windows x64 和 ARM64 的便携 Node.js 及锁定的运行依赖。完整解压 ZIP 后保存工作并正常退出客户端，再双击 `install.cmd`。补丁完成后使用原有快捷方式打开 Antigravity。恢复英文时退出客户端，再运行 `restore.cmd`。安装和还原均可离线进行。

官方更新覆盖补丁后，核对新客户端版本和原版资源，再用对应安装包重新应用。固定界面译文随安装包内的 `dictionary.json` 发布。

## 发布

本地 `D:\反重力汉化` 只保留当前客户端版本最近一次验证通过的手动安装 ZIP。确认发布包的 SHA-256 后，清理本项目的本地旧安装包和临时 ZIP 副本。同版本客户端原版备份按版本适配规则保存。

GitHub 按 Antigravity 客户端版本各保留最后一份已验证的适配包。发布标题写明主要适配的 Antigravity 版本，正文记录兼容验证、改动和限制。通过 `scripts/build-offline-release.ps1 -OutputDirectory <隔离目录> -NpmCli <npm-cli.js 路径>` 从指定提交打包，再核对源码和 `runtime/manifest.json`。脚本在构建端安装锁定依赖，将官方 Node.js 和许可证一起打入 ZIP。上传前从离线 ZIP 解包，用精简的 Windows PATH 实测 `install.cmd` 和 `restore.cmd`，核对同版本原版还原及外置资源。公开后匿名重新下载 ZIP 和校验文件，核对标签、主分支提交、清单和 SHA-256，再确认保留清单上的安装包仍公开可下载。

指定 `-ClientVersions 2.34.0,2.33.0,2.32.2,2.32.1` 可从同一个提交分别生成对应客户端的离线包。每个包的 `clientVersion` 写入运行时清单，安装和还原会核对实际 ASAR 的版本。逐个验证正版归档和跨版本误装拦截，再逐个替换 GitHub 对应的旧附件。

当前公开下载按主要适配版本保留。Windows 2.35.1 → v1.2.4，2.34.0 → v1.2.5-ag2.34.0，2.33.0 → v1.2.5-ag2.33.0，2.32.2 → v1.2.5-ag2.32.2，2.32.1 → v1.2.5-ag2.32.1。
